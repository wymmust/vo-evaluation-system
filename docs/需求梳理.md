# 二、sf_vloc
## 1. 输入
- data_dir
- log_dir

`data_dir`是真实值所在目录，`log_dir`是估计值所在目录；

> 之所以要求传入目录，是因为要加载除了轨迹文件之外，还要加载标定参数文件、home_point文件等。

## 2. 关键数据格式定义

### 2.1 imu.txt格式定义
导航数据轨迹文件路径：`${data_dir}/imu.txt`

文件格式为每行一个时间戳和对应这一时刻的导航信息，共21列，具体格式如下：
```
ts ts_fcc status flight_mode x y z yaw pitch roll vx vy vz position_reset_count, altitude_reset_count, heading_reset_count, latitude, longitude, altitude, altitude_msl, height
```
- `ts`：时间戳（秒）,与图像的时间戳是同一基准
- `ts_fcc`: 时间戳（秒），FCC平台的时间戳基准
- `status`: 状态，最后4比特记录导航模式navi_mode(status & 0x0F)，第22比特位记录rtk_yaw，第28比特位记录rtk_alitude
- `flight_mode`: 飞行模式
- `x, y, z`：位置坐标
- `yaw, pitch, roll`: 姿态的欧拉角表示，顺序为航向角、俯仰角、滚转角，单位：弧度
- `vx, vy, vz`: 三个维度的速度
- `position_reset_count, altitude_reset_count, heading_reset_count`: 位置、高度、航向重置次数
- `latitude, longitude, altitude, altitude_msl, height`: 经度、纬度、高度、高度msl、雷达探测高度

> 导航位姿均在机体坐标系(body系)下

### 2.2 vloc.txt格式定义

vloc数据轨迹文件路径：`${log_dir}/vloc.txt`

文件格式为每行一个时间戳和对应这一时刻的相关信息，共13列，具体格式如下：
```
ts status num_inliers reset_count x y z yaw pitch roll latitude, longitude, height
```
- `ts`：时间戳（秒）,图像的时间戳是同一基准
- `status`: 状态，最后4比特是vloc_mode(status & 0x0F)
- `num_inliers`: 内点数量
- `reset_count`: 重置次数
- `x, y`: 水平位置
- `z`: 海拔高
- `yaw, pitch, roll`: 姿态的欧拉角表示，顺序为航向角、俯仰角、滚转角，单位：角度
- `latitude, longitude`: 经度、纬度
- `height`: 对地高

> vloc位姿是在相机模块的imu坐标系下

### 2.3 home_point.txt格式定义
home_point记录vloc启动时的home点信息，文件路径：`${log_dir}/home_point.txt`

文件只有一行3列，记录经纬高
```
longitude latitude altitude_msl
```
- `longitude`: 经度
- `latitude`: 纬度
- `altitude_msl`: 海拔高

## 3. 数据预处理

### 3.1 通过home_point，统一转到NED坐标系
将nav_data和vloc_data的经纬高`latitude, longitude, altitude_msl`转为以home_point为原点的NED（北东地）坐标系

> 注意，此时nav_data的NED

### 3.2 时间戳对齐与坐标系对齐
1. 筛选有效的VLOC数据： 
- vloc_mode > 1
- ts在nav_data的ts范围内
2. 以有效的VLOC数据为基准，对nav_data进行插值，nav_data各数据项插值原则如下：
- `status, flight_mode, reset_count`采用最邻近插值
- `x, y, z, vx, vy, vz, latitude, longitude, altitude, altitude_msl, height`采用线性插值
- `yaw, pitch, roll` 欧拉角表示的姿态。 无法直接用欧拉角插值，应转为四元数表示的姿态，再进行球面线性插值（slerp）。 

3. 坐标系对齐：vloc_data在imu系下，nav_data是在body系，需要使用`T_imu_body`将vloc_data转为body系下。统一在body系下进行计算。
- vloc_data下`x, y, z`转为body系下`x, y, z`
- vloc_data下`yaw, pitch, roll`转为body系下`yaw, pitch, roll`
- vloc_data下`ned`转为body系下`ned`

## 4. 轨迹对比

### 4.1 位置误差计算

位置误差: `nav_data.ned - vloc_data.ned`

### 4.2 姿态误差计算

转为旋转矩阵计算误差：

$$
R_{error} = (R_{wb}^{ref})^{-1}R_{wb}^{est}
$$

转回欧拉角，方便可视化

### 4.3 轨迹长度及误差统计

1. 轨迹长度traj_length: 相邻时间戳的`nav_data.ned`的L2范数之和。
2. 水平位置平均/最大误差
3. 垂直位置平均/最大误差

```
ts num_inliers x y z yaw pitch roll is_keyframe, time_cost, reset_count
```

- `num_inliers`: 内点数量
- `x, y, z`: 位置
- `yaw, pitch, roll`: 姿态的欧拉角表示，顺序为航向角、俯仰角、滚转角，单位：角度

> vo位姿是在cam系下

## 3. 数据预处理

### 3.1 VO有效段筛选
以vo_data.reset_count字段为基准对Vo数据进行分段：
- reset_count连续相同的行为同一段vo；
- reset_count发生变化时，说明Vo失效后重新初始化了，是新的Vo段；

对于每个Vo段，取其首尾时间戳，作为该段的有效时间范围。有效时间范围小于10s或有效帧数小于200帧的Vo段，认为是无效的，剔除。后续只处理有效Vo段。

### 3.2 时间戳对齐与坐标系对齐

1. 以有效的VO数据为基准，对nav_data进行插值，nav_data各数据项插值原则如下：
- `status, flight_mode, reset_count`采用最邻近插值
- `x, y, z, vx, vy, vz, latitude, longitude, altitude, altitude_msl, height`采用线性插值
- `yaw, pitch, roll` 欧拉角表示的姿态。 无法直接用欧拉角插值，应转为四元数表示的姿态，再进行球面线性插值（slerp）。 

3. 坐标系对齐：vo在cam下，nav_data是在body系，需要使用`T_imu_body`和`T_cam_imu`将vo_data从cam转到imu，再转到body系下。统一在body系下进行计算。
- vo_data下`x, y, z`转为body系下`x, y, z`
- vo_data下`yaw, pitch, roll`转为body系下`yaw, pitch, roll`

### 3.2 Sim3对齐

分别处理每个有效的Vo段：
1. 计算当前Vo段Sim3变换参数：对齐两个坐标系之间的缩放、旋转和平移关系。（Umeyama算法）
2. 对当前Vo段应用Sim3变换：将VO数据转换到与导航数据相同的坐标系下。
